# R7.2 — полный комплект DEMO

В пакете новый APK и полный Bridge одной ревизии. Android SDK/Android Studio на компьютере пользователя не нужны. REAL отключён в адаптере. Это исследовательская DEMO-версия, не доказательство прибыльности и не гарантия точного будущего.

## Установка
1. Выключите AUTO и дождитесь завершения кампаний бота/подтверждения заявок. Закройте Bridge. MT5 закрывать необязательно.
2. Распакуйте ВЕСЬ ZIP. Запустите INSTALL_R7_2.cmd. Установщик покажет существующую папку Bridge; проверьте путь. По умолчанию проверяется OneDrive/Documents/GitHub/FX-M1-Signal/mt5_bridge; при отсутствии предлагается новая папка Bridge из архива. Можно ввести другой полный путь. Введите YES.
3. При успехе будет `OK: R7.2 installed`. Запустите START_BRIDGE_V10_0.bat ИМЕННО из папки, указанной установщиком. Он использует прежнюю .venv, если она есть. Для свежей установки нужен Windows Python 64-bit с MetaTrader5; требования перечислены в requirements_event.txt. SDK не нужен.
4. Установите FXM1_R7_2_DEMO.apk поверх текущего приложения, НЕ удаляя его. Подпись сохранена. В статусе должны быть 10.9-EC1-R7.2 и R7.2-DEMO.
5. Проверьте адрес, ключ и тип DEMO. Выберите инструмент/таймфрейм/режим и отдельно включите AUTO. Новые профили, обновление и перезапуск сами не дают разрешения торговать.

База campaign.sqlite3, WAL/SHM, ключ, .venv и broker-clock.json не удаляются. Установщик проверяет остановку Bridge и незавершённые кампании, сохраняет программу в r72_program_backup_*. Откат: ROLLBACK_R7_2.cmd с тем же путём, только при остановленном Bridge и завершённых кампаниях. Само приложение при откате не понижается автоматически.

## Что изменено
- Сохранены HF1/HF2: готовые NORMAL-кандидаты не исчезают из-за отображения; непригодная геометрия убирается; причины закрытия MT5 сохраняются без догадок.
- Независимый исследовательский прогноз отображается при WAIT. Это временная оценка по сопоставимым историческим изменениям, а не обещанная будущая свеча. Исходные прогнозы сохраняются; результат оценивается после появления цены.
- Рабочий период входит в расчёт движения, отката и стопа. NORMAL дополнен подтверждённым продолжением без обязательной большой фигуры. SCALP ищет наблюдаемое движение, откат и новый локальный пробой на выбранном периоде. Стоп учитывает локальную структуру и спред; NORMAL использует более широкую опору. Не открывает по таймеру или одной стрелке прогноза.
- Профили разных брокерских инструментов изолированы и могут быть явно включены по отдельности. Один центральный последовательный владелец исполнения; один исполняемый профиль на инструмент. Переключение инструмента не переносит его сделки в другую кампанию.
- Добавления идут по новым подтверждениям, а не повтором одного тика; усреднение убыточной группы запрещено. Фиксируется исходный прогноз кампании.
- Исправлены старые ответы сети после смены инструмента. Выбор известного инструмента восстанавливает его период/режим/лот/риск. Emergency применяется ко всем профилям счёта.

## Поддержка и ограничения
Проверенные искусственными последовательностями торговые периоды: M1, M5, M15, M30, H1, H4, D1, W1, MN1; это проверка логики, НЕ рыночная аттестация доходности. M10 не добавлен в интерфейс.
Временной прогноз не подменяет крупный период мелким: M1/M5 допускают 5/10/15/30/60 минут при достаточной истории; M15 — 15/30/60; M30 — 30/60; H1 — 60; H4/D1/W1 — 1/2/3 рабочих бара. Для календарного MN1 временной прогноз пока явно недоступен, торговая логика и история сохраняются.
Общая расчётная граница риска счёта равна максимальному выбранному проценту профилей, а не этому проценту на каждый инструмент одновременно. Она показывается в состоянии/диагностике. Перед новой заявкой считаются все открытые позиции и расход маржи. Несколько неизвестных результатов/заявок не отправляются повторно. Автоматический запрет по произвольным двум/трём минусам не добавлен.
При недостаточном минимальном лоте, данных, марже или неподтверждённом исполнении сделка не форсируется. WAIT с конкретной причиной допустим.

## Проверка
Verification содержит результаты Python, нативного Android API35 и нативного Windows-установщика. PROVENANCE.json и SHA256SUMS.txt связывают комплект с одним коммитом. Ключ подписи, пользовательские базы/токены в ZIP не включены. Живой брокерский MT5 и физический телефон в CI не испытывались. Точность прогноза на будущем рынке и доходность не установлены.


## R7.2 — стабильный runtime по старой схеме
- План входа показывается для NORMAL и SCALP на выбранном рабочем периоде, а не только для SCALP M1.
- Если геометрическая фигура отсутствует, экран показывает фактический этап подготовки входа вместо противоречивого «нет ясной структуры».
- Пустой раздел гипотез не занимает место; динамические блоки не резервируют пустые строки.
- «Плановый риск» переименован в лимит риска кампании, чтобы не воспринимался как ожидаемый убыток.
- Launcher проверяет установленный Flask/Colorama и при неполной библиотеке переключается на комплектный _vendor.


### Почему R7.2 заменяет R7.1
- Удалён runtime `_vendor`: Bridge снова запускается через обычный проверенный `.venv`, как рабочие версии до R7.
- Установщик полностью заменяет программный `event_core` копированием, а не переименованием каталогов через `os.replace`; это исключает обнаруженный конфликт OneDrive/WinError 5.
- Colorama 0.4.6 входит в пакет только как офлайн-зависимость для восстановления существующего `.venv`; она не добавляется в `sys.path` приложения.
- После установки обязательно проверяются MetaTrader5, Flask, Colorama, VERSION/BUILD EventCore и импорт Bridge. Реальная Python-ошибка не скрывается.
- База, WAL/SHM, токен, broker-clock и торговая история не заменяются.
