# FX M1 EventCore EC1 — R3 REBUILD

Совместимость APK/Bridge: **10.9-EC1**  
Сборка: **10.9-EC1-R3-REBUILD**  
Протокол: **fxm1.event.v1**

Это DEMO-only исследовательская сборка. Решение о входе, риск, отправка и сопровождение принадлежат Bridge/EventCore. Android только показывает состояние Bridge и отправляет явные команды управления.

## 1. Иерархия данных R3

EventCore разделяет закрытую историю и текущую формирующуюся свечу:

- **H1** — старший контекст. Подтверждённое противоположное направление блокирует новый вход.
- **M15** — промежуточный контекст с тем же правилом блокировки против направления.
- **закрытые M5** — основная карта структуры. HH/HL/LH/LL строятся только по подтверждённым pivot-точкам; формирующаяся M5 не участвует в вычислении swing-структуры.
- **текущая M5** — используется только для пути `IMPULSE`, отдельно от закрытой истории.
- **закрытые M1** — подтверждают момент входа.
- **живой tick/quote** — финально подтверждает цену и свежесть события.

Android получает `decision.path`, `decision.structure`, уровни и свечи из `/ec/state`. Локального расчёта pivot, направления или права на вход в APK нет.

## 2. Пути входа

### IMPULSE

Быстрый вход разрешается только когда большая **текущая M5** одновременно проходит все проверки:

- тело не меньше **0.70 ATR** закрытых M5;
- полный диапазон не меньше **1.00 ATR**;
- отношение тела к диапазону не меньше **0.65**;
- свеча пробивает последний подтверждённый swing-уровень;
- закрытая M1 уже находится за trigger в том же направлении;
- живой bid находится за trigger;
- M15/H1 не подтверждают противоположный контекст;
- подтверждённая M5-структура не направлена против импульса;
- цена не ушла дальше допустимого `no_chase`.

Один размер свечи сам по себе вход не создаёт.

### CONTINUATION

Продолжение ищется только в подтверждённом направлении структуры. Перед новым входом должна быть реальная неглубокая пауза/коррекция: retrace не меньше **0.10 ATR** и меньше **0.35 ATR**. После постановки trigger требуется **новая закрытая M1** за уровнем и свежий tick за тем же уровнем. Непрерывная серия свечей по тренду не переименовывается в continuation-вход.

### PULLBACK

Более глубокий откат/ретест остаётся отдельным путём `PULLBACK`. EventCore ждёт подтверждённый откат и затем свежее пересечение локального trigger. Для NORMAL порог pullback-профиля — **0.35 ATR**. Вход не разрешается старым сигналом после отмены структуры, истечения setup или чрезмерного ухода цены.

Для **NORMAL/M5** срок жизни pending setup равен ровно **3 закрытым M5 = 15 минутам**. Новый валидный event того же направления может заменить старый pending-сценарий; старого 40-минутного lock нет.

## 3. Защита от будущих данных

`MT5Broker.bars()` передаёт стратегии только закрытые свечи. `current_bar()` получает формирующуюся M5 отдельно. Pivot становится доступен только после закрытия требуемых свечей справа; HH/HL/LH/LL не используют будущую свечу. Android не дорисовывает будущую цену и не добавляет синтетическое продолжение графика.

## 4. Риск и исполнение

Размер риска кампании считается от **фактического счёта MT5**: используется `min(balance, equity) × risk_pct`. Искусственная база 100 USD и старый absolute-dollar cap не заменяют реальный balance/equity. По умолчанию профиль использует 0.25% риска и lot cap 0.01, если пользователь не изменил допустимые настройки.

Сохраняются действующие ограничения EventCore: дневной лимит, просадка, серия убытков, spread, margin, rate-limit, technical position fuse, cooldown, контроль чужих позиций и reconciliation. Добавления в кампанию разрешаются только через риск-модель; усреднение убыточной позиции не является основанием для нового входа.

## 5. DEMO и REAL

Отправка ордера проходит через `MT5Broker._demo()`. Нужен торгуемый **DEMO hedging** счёт. REAL/contest и неподходящий режим счёта блокируются до `order_send`. R3 REBUILD не включает переключатель, обходящий эту защиту.

## 6. AUTO, PAUSE и Emergency

Состояние AUTO принадлежит Bridge. Уход из Activity, recreation Android-экрана или временный обрыв связи телефона не отправляют команду `disable` в Bridge. Управление выполняется только явными командами пользователя/системы: PLAY, PAUSE, disable или Emergency.

Emergency latch сохраняется как защитное состояние; обычный PLAY не должен самовольно снимать Emergency. Сопровождение уже открытой кампании отделено от разрешения новых входов.

## 7. Что показывает Android

APK сохраняет существующие экраны, журнал, историю денег, кнопки PLAY/PAUSE/Emergency и свечной график. На графике R3 дополнительно отображается только подтверждённая структура Bridge: тонкая линия между видимыми swing-точками и метки HH/HL/LH/LL. Отдельно показывается локализованный путь: Импульс / Продолжение / Откат / Триггер / Поиск.

## 8. Проверка сборки

R3 CI выполняет:

1. Python `compileall` и полный `unittest discover` на реальном EventCore с fake MT5;
2. сборку APK и instrumentation APK;
3. API 35 emulator suite с реальным Flask/Engine fixture;
4. проверки свечей, R3 structure/path, AUTO persistence, notification controls и Emergency latch;
5. упаковку APK/Bridge/source строго из одного проверенного commit SHA;
6. SHA-256 APK и `PROVENANCE.json` с `real_trading: blocked`.

Эти тесты подтверждают механику, безопасность состояний и отсутствие известных регрессий. Они **не являются backtest/forward-test и не доказывают прибыльность стратегии**.
